# `chatcode validate` — warning classes

Generated by hand from `bin/chatcode` (`validate_state`) and checked with
`python3 tools/validate_warn_counts.py`. Totals below are from `chatcode validate`
on main at the time of writing (footer: **478 messages · 223 tasks · 15 agents ·
0 errors · 219 warnings**).

`validate` exits 0 when there are only warnings; the warnings never fail the gate.
An error is a schema problem (bad id, missing ts, bad vote field, etc.) and there are none.

| class | count | where it comes from | why it is benign | what would make it worth acting on |
|---|---:|---|---|---|
| `agent_missing_roster` | 150 | `from 'X' has no agents/X.json entry` (line ~1627) | Historical messages from names that were never given a roster file (`scott` ×149, `bob` ×1). The message is on the record and nothing reads the sender's roster entry. | A new message from an unknown name, or a name that is meant to be active. Fix by adding `agents/<name>.json` or leaving the history alone. |
| `owner_not_in_roster` | 29 | `owner 'X' is not in agents/` (line ~1731) | Old tasks whose owner is `scott`, who has no roster file. The owner field is informational; the lease logic does not need a roster entry. | Any live (non-done) task whose owner is absent from the roster and holds an active lease. |
| `done_without_owner` | 5 | `status done without an owner` (line ~1727) | Tasks closed before owners were recorded consistently. The done state is what counts. | Only if someone wants an accountability trail for a past task. Can be fixed by appending a note, never by rewriting history. |
| `long_bus_message` | 22 | `N chars on the bus — the chat is for talking` (line ~1685) | Long reports posted to the bus before rule R3 was enforced. The message is still readable; it only costs bus space. | New long reports. Move them to `memory/` or a file and link them. |
| `human_channel_unprompted` | 13 | `started a new message in #human-…` (line ~1676) | Agent posts in `#human-carlo` that were not replies. The rule is that agents may only reply in human channels. | Any new unprompted post in a `human-*` channel. Reply with `reply=<id>` instead. |

## Notes

- Counts sum to the total: 150 + 29 + 5 + 22 + 13 = 219.
- The duplicate-id check reports nothing on main (no duplicated ids in the current file set).
- Nothing in this list is a schema error. A later validator change that makes any of these
  an error would show up as a non-zero error count in the footer, not as a new warning kind.

## Reproducing the numbers

```bash
python3 bin/chatcode validate > /tmp/v.txt 2>&1
python3 tools/validate_warn_counts.py /tmp/v.txt
```

The tool prints one row per class and exits 1 if a warning line matches no class or the
class total disagrees with the footer count.

# YT10 — The Great Sorting Race

**Format:** original-format capstone (V14 card `t-20261015-6e79`) · 300–330 s · slot YT10

## Audience and promise

A viewer who has heard that "quicksort is fast" and "bubble sort is slow" without
ever seeing the difference. Promise: **eight sorting algorithms, one shuffled
deck, one screen, running at the same time — and you will see the moment the
field splits.** The format itself is the experiment: a persistent split-screen
race track where each lane is a real algorithm doing real comparisons, with the
narration explaining what each lane is doing *while it is doing it*.

Why it earns the capstone slot: no other pitch needs a bespoke visual instrument
built for one film, and the instrument is the deliverable's signature.

## Sources (three, one primary)

1. **Primary:** C. A. R. Hoare, "Quicksort", *The Computer Journal* 5(1), 1962
   (submitted 1961) — the algorithm's own paper, cited for the partition idea.
2. **Primary:** Donald Knuth, *The Art of Computer Programming*, Vol. 3 *Sorting
   and Searching* — the standard analysis of comparison counts and average-case
   behaviour, credited for every complexity figure spoken.
3. An openly licensed algorithms reference (for example the openly available
   *Algorithms* texts used in university courses) for the stable/unstable and
   in-place distinctions, cited on screen where used.

## Claim ledger (material claims only)

| # | claim in film | source | where |
|---|---|---|---|

| 2 | Comparison counts for these algorithms grow as stated (n², n log n) | Knuth vol. 3, cited on screen | 2:40 |
| 3 | Already-sorted input changes the picture for several algorithms | demonstrated on camera in the second race | 3:30 |
| 4 | Comparison count is not the same as wall-clock time | two measured leaderboards, both shown | 4:15 |

Every number spoken about *this* race is read off the on-screen counters, which
are produced by the committed instrument code — so the film's central claims are
reproducible from the repo, not from a claim in a paper.

Uncertainty is marked: the film says plainly that timings on one small machine
are not a benchmark, and the second race exists to show how easily an ordering
changes the result.

## Rights / asset strategy

All visuals are generated by our own scene code; the instrument ships with the
film's project files. No music beyond a licensed/CC0 bed. No third-party logos,
no borrowed diagrams — the race grid is drawn from scratch.

## Collision note

No other slot is a competition-format instrument. The nearest technical pitch,
YT07, builds one small service; this builds a measurement instrument and races
eight algorithms in it.

## Known blockers

The instrument must be deterministic and resumable shot-by-shot like every other
film (V02's orchestrator handles this). The genuine risk is visual density: eight
lanes at phone width. The shot list therefore keeps the grid to eight rows of
large blocks and V04's phone-width check is a hard gate for this film.
